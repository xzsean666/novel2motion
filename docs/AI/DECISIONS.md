## 历史架构决策 (ADR-001 ~ ADR-007)

- **ADR-001**: 采用“固定角色锁定 + 差分表情映射”解决 AI 角色漂移问题。
- **ADR-002**: 建立“背景标签语义匹配与复用池”，避免每镜头重新生图。
- **ADR-003**: 采用五槽位 (`FarLeft`, `Left`, `Center`, `Right`, `FarRight`) 画布舞台空间编排标准。
- **ADR-004**: 对白时间对齐与 BGM 自动闪避 (-14dB Audio Ducking)。
- **ADR-005**: 打斗动效映射（重击、震屏、白闪、剑光）。
- **ADR-006**: 资产分层与包围盒漫水填充不透明抠图标准。
- **ADR-007**: 短视频爆款大字描边排版标准（马善政毛笔行楷，金黄填充 + 纯黑厚重描边）。

## 现代架构重构决策 (ADR-008 ~ ADR-012)

### ADR-008: 全面转向 Node.js (TypeScript) + Three.js 现代视觉动效引擎

- **背景**: 之前采用 Rust 纯 CPU 逐像素合成（`image` 库）存在严重技术瓶颈：缺乏骨骼关节动画、缺乏 3D 摄像机平滑运镜、缺乏粒子系统与物理缓动，导致生成画面僵硬死板、画质发虚，每次调整表情都需要手工编写漫水填充脚本。
- **决策**:
  - 彻底废弃 Rust CPU 软件光栅化，将全栈架构切换为 **Node.js (TypeScript) + Three.js**。
  - 利用 Three.js 成熟的场景图、透视/正交摄像机、网格材质（Mesh/Material）、粒子系统与着色器，全面提升视觉表现力。
- **结果**: 获得工业级视频动效能力，画面彻底告别发虚与僵硬，支持电影级运镜与生动肢体动作。

### ADR-009: 底层 SDK 强制通过 GitHub + Commit Hash 安装规范

- **背景**: 系统需要深度依赖已优化好的两个核心 SDK：数据库库 `/ssd0/git/kvdb-nodejs` 与运行时调度库 `/ssd0/git/NodeJS-Task-Runtime`。如果在 `package.json` 中使用本地路径（`file:..`），会导致脱离环境无法构建，且破坏依赖锁定。
- **决策**:
  - **严禁** 在 `package.json` 中配置任何本地相对路径或 npm link。
  - **必须** 采用 GitHub 仓库结合具体 Commit Hash 进行依赖固定：
    - `kvdb-sdk`: `github:xzsean666/kvdb-nodejs#<commit-hash>`
    - `node-task-runtime`: `github:xzsean666/NodeJS-Task-Runtime#<commit-hash>`
  - **本地修复闭环**: 若两个 SDK 存在 Bug，AI 代理可直接在对应本地目录修复、测试（账号 `xzsean666`），推送到 GitHub 并获取新 Hash 后，回写到本工程的 `package.json`。
- **结果**: 保证跨环境一键安装构建，同时保留在本地同级目录快速迭代修复 SDK 的能力。

### ADR-010: Three.js 2.5D 分层纸片人傀儡 (Paper Doll Rig) 与魔性人脸体系

- **背景**: B 站爆款沙雕仙侠推文动画（如“万人敬仰韩天尊”）的核心幽默感来自于“仙风道骨的成男御剑飞行身姿”与“夸张魔性真人表情（张学友、白须老祖）”的强烈反差。
- **决策**:
  - 在 Three.js 中实现层次化纸片人傀儡 Mesh：飞剑层、躯干层、双臂层、头部层分级联动。
  - 角色头部预留材质 UV，真人魔性脸（张学友经典“食屎啦你”表情、白须老祖脸）作为独立材质纹理，在发髻发丝遮罩下动态平滑嵌合。
- **结果**: 动作具备呼吸起伏与御剑倾斜动态，表情切换即时生效，完美还原爆款推文动画质感。

### ADR-011: 基于 `kvdb-sdk` 的持久化、多级缓存与可靠渲染队列

- **背景**: 视频生成是重型计算任务，小说解析、TTS 配音与长视频渲染需要可靠的持久化与任务队列。
- **决策**:
  - 引入 `kvdb-sdk`，利用 SQLite 后端持久化角色圣经表与背景资产表。
  - 使用 `kvdb-sdk` 的独立缓存池（`Cache`）持久化对白 TTS 语音与 LLM 响应，实现毫秒级命中复用。
  - 使用 `kvdb-sdk` 内置的 `db.queue("render_jobs")` 承载渲染任务，自带原子租约（Atomic Lease）、可见性超时（Visibility Timeout）与指数退避重试，零外部 Redis 依赖。
- **结果**: 架构极简稳定，单文件 SQLite 数据库开箱即用。

### ADR-012: 基于 `node-task-runtime` 的进程流控、临时目录防泄漏与工作线程池

- **背景**: 渲染管线涉及高频调用 FFmpeg 子进程、处理二进制图像帧、以及大量的数学缓动与文本分块计算。如果不加控制容易发生内存泄漏、临时目录垃圾堆积或僵尸进程。
- **决策**:
  - 引入 `node-task-runtime` 作为全系统的执行中枢：
    - 使用 `runtime.cli` 封装 FFmpeg 执行，实时监听进度，内置超时与防僵尸进程保护。
    - 使用 `context.createTempDir()` 管理每场分镜的临时帧文件，执行完毕自动清理。
    - 使用 Worker Threads 工作池分担 CPU 密集的时间轴计算与状态编译。
- **结果**: 彻底消除进程与文件泄漏隐患，系统具备企业级容错与高并发处理能力。

### ADR-013: 立绘蒙皮实际接入离线渲染与事件时序修复

- **背景**: 实际读取发现旧离线出片将角色整体 PNG 直接绘制，未使用头部/双臂动作；镜头和命中特效逐帧重启。历史验收只检查编码参数，不能证明动画质量。
- **决策**: 使用现有 Three.js `Skeleton`、`SkinnedMesh` 和归一化骨骼权重驱动头、双臂、衣摆及发丝。Skia 离线光栅化消费真正的蒙皮顶点，面部细节先绘入纹理后一起变形。复用现有 PNG，不引入 Spine 商业运行时。
- **时序**: 对白镜头在事件进入时启动；camera/sfx 附着于剧情事件，不额外占用时长；近战和法术在进度 58% 时触发命中，配对 hit 不重复播放。配音结束后停止口型。
- **参考**: Spine 官方 Spineboy 示例、Mesh attachments 文档，链接见 TASK-127。
- **边界**: 当前是基于单张立绘的 2D 网格骨骼动画，仍由 Skia 输出像素，并非 Three.js WebGL/PBR 的完整 3D 渲染。幅度需适度；背面、转身、复杂走跑和大幅遮挡需要分层原画或 3D 角色资产。
- **验收**: 以可见动作、连续抽帧、局部像素变化和命中次数为依据，视频分辨率与码率不作为艺术质量已达标的证据。

### ADR-014: 全面跃迁工业级 AI 短剧/漫剧全流程架构 (Generative AI Mini-Drama Pipeline) 与剪映工程互通

- **背景**: 用户指出系统过去方向完全不符合现代“短剧”预期：单纯在 2D 贴图上加伪口型和皮影戏式抽动只是早期的沙雕搞笑动画。真正的 AI 短剧需要影视级分镜、AI 扩散视频生成（可灵/海螺/通义万相）、角色人设一致性锚定、真实微表情以及多轨道音画剪辑。
- **决策**:
  - 新建短剧领域流水线 `src/drama/`，全面引入短剧工业化标准：
    1. **短剧编导引擎 (`DramaDirector`)**: 黄金 3 秒冲击钩子、景别（大特写、特写、中景、全景）、运镜语言（Dolly In/Out, Pan, Whip Zoom）、双语提示词与情绪对白。
    2. **角色一致性设定库 (`CharacterBible`)**: 锁定角色外貌特征、参考图与 LoRA/IP-Adapter 权重。
    3. **多模型视频生成适配器 (`IVideoGeneratorProvider`)**: 抽象统一驱动快手可灵 (Kling AI)、MiniMax 海螺 (Hailuo AI)、阿里通义万相 (Wan 2.1)，并内置高保真电影级运镜回退引擎 (`CinematicMotionProvider`)。
    4. **剪映/CapCut 桌面工程草稿导出器 (`JianyingDraftExporter`)**: 一键生成 `draft_content.json`，支持创作者在剪映中直接打开精修二次剪辑。
    5. **影视级视听合成器 (`DramaComposer`)**: 9:16 移动端竖屏主流画幅、FFmpeg 蒙太奇拼接、情绪 TTS 配音、SFX 音效、智能 -16dB 闪避混音与爆款花字字幕。
- **结果**: 彻底打破 2D 纸片人玩具瓶颈，实现真正符合市场预期的现代工业级 AI 短剧/漫剧生成能力。

### ADR-015: 声明式模块化人物建模体系 (Declarative Modular Avatar System) 与通用骨骼动作/换装架构

- **背景**: 过去角色依赖“单张死板立绘 + 简单形变”的固化模式，导致换套衣服或换个发型需要重新画整张图，各角色无法复用动作，面部风格单一且肢体僵硬。用户明确要求重构人物建模体系：“他们有通用的动作，面部有不同风格建模，身体也有男女各种情况建模尽量通用，人物靠不同装饰头发、衣服来区别。一个人就是一串 JSON，服装可以不断更新，动画效果更好”。
- **决策**:
  1. **纯 JSON 声明式角色契约 (`ModularAvatarSpec`)**:
     - 彻底解耦角色外貌与代码实现，角色完全由纯 JSON 数据结构定义（包含 `gender`, `archetype`, `face`, `hair`, `costume`, `sockets`, `dynamics`）。
     - 服装分层拆解（内衬 inner、外袍 outer、腰带 sash、披风 cloak、下装 bottom、鞋履 shoes、护甲 armor），支持独立热插拔换装与更新。
  2. **男女与体型基础骨骼拓扑 (`UniversalBodyArchetypes`)**:
     - 建立标准化骨骼层次体系（Root -> Pelvis -> Spine/Chest -> Neck/Head + 双臂 + 双腿 + Sockets + 柔性骨骼）。
     - 支持成男 (`male_adult`)、成女 (`female_adult`)、少年 (`male_youth`)、少女 (`female_youth`)、力士 (`male_muscular`)、仙翁 (`male_elder`) 等多体型标准比例。
  3. **多风格面部与微表情/音素口型引擎 (`MultiStyleFaceEngine`)**:
     - 抽象面部风格（玄幻国风写实、现代二次元动漫、国漫热血、幽默Q版）。
     - 解耦五官网格与材质层，结合 TTS 能量实现精准音素口型（Viseme: silence, a, i, u, e, o, m）与眨眼/眼神注视/微表情特效。
  4. **通用动作库与骨骼映射 (`UniversalMotionLibrary`)**:
     - 动作彻底解耦于具体角色，输出通用的关键帧姿态变换与受力参数，普适于所有体型。
  5. **二级动力学物理层 (Secondary Dynamics)**:
     - 为长发、大袖、下摆、披风增加基于阻尼弹簧的二级动力学摆动，在动作和气流吹拂下呈现自然舒展的动效。
- **结果**: 实现真正的“角色即 JSON”，服装/配饰/发型可无限模块化扩充，动画品质与复用度产生质的跃升。
